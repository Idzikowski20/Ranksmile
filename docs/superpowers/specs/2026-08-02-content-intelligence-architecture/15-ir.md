# 15 — Intermediate Representation (IR)

## Pipeline

```text
Lexical AST → Semantic AST → IR → PassManager (builders) → CCM Snapshot
```

Semantic AST describes **text**. IR describes **meaning candidates**.

## Naming

Avoid overloaded `FactCandidate` as the umbrella term.

```text
SemanticCandidate          (base)
  ├── EntityCandidate
  ├── FactCandidate        (typed)
  ├── RelationCandidate
  ├── IntentCandidate
  ├── QuestionCandidate
  └── TopicCandidate
```

```ts
export type SemanticCandidateKind =
  | 'entity' | 'fact' | 'relation' | 'intent' | 'question' | 'topic';

export interface SemanticCandidate {
  readonly id: string;
  readonly kind: SemanticCandidateKind;
  readonly confidence: number;
  readonly blockIds: readonly string[];
  readonly claimId?: string;
}

export interface FactCandidate extends SemanticCandidate {
  readonly kind: 'fact';
  readonly statement: string;
  readonly subject?: string;
  readonly predicate?: string;
  readonly object?: string;
  readonly entityCandidateIds: readonly string[];
}

export interface ContentIr {
  readonly version: 1;
  readonly contentHash: string;
  readonly paragraphs: readonly IrParagraph[];
  readonly claims: readonly IrClaim[];
  readonly candidates: readonly SemanticCandidate[]; // typed via kind discriminant
}
```

Typed candidates are narrow interfaces extending `SemanticCandidate`. Passes filter `candidates` by `kind`.

## Builder input rule

Passes/builders discover from **IR candidates**. AST only for span anchors. No HTML discovery when IR present.

## Invariant

`capabilities.ir === true` for all non-adapter CCM snapshots.
